# Цифровой помощник тьютора - модуль обработки наблюдений

Решение тестового задания для Data Scientist: пайплайн интеллектуальной
обработки неструктурированных текстовых записей о детях с ОВЗ.

Модуль решает три задачи:

1. **Извлечение полей** из текста (`date`, `child_id`, `author`, `sleep_hours`, `zone`).
2. **Классификация типа записи** (`observation`, `lesson_report`, `parent_note`, `recommendation`, `unknown`).
3. **Проверка отнесения наблюдения** к отслеживаемым зонам развития (8 зон).

Пайплайн работает **без API-ключей** (на эвристиках) и опционально
подключает **GigaChat** для повышения точности.

## Требования

- **Python 3.11+**
- pip / venv
- (опционально) переменная окружения `GIGACHAT_CREDENTIALS` для работы LLM

```bash
python --version   # ожидается Python 3.11.x или выше
```

## Установка зависимостей

### 1. Клонировать репозиторий

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd tutor_assistant
```

### 2. Создать виртуальное окружение

```bash
python -m venv .venv
```

Активировать:

- **Linux / macOS:**
  ```bash
  source .venv/bin/activate
  ```
- **Windows (PowerShell):**
  ```powershell
  .venv\Scripts\Activate.ps1
  ```
- **Windows (cmd):**
  ```cmd
  .venv\Scripts\activate.bat
  ```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

Или через `pyproject.toml`:

```bash
pip install -e ".[dev]"
```

Для работы с LLM дополнительно:

```bash
pip install -e ".[llm]"
```

## Запуск пайплайна

Все команды выполняются из корня репозитория.

### Прогнать все три части

```bash
python main.py --all
```

### Запустить отдельные части

```bash
python main.py --extract      # Часть 1: извлечение полей
python main.py --classify     # Часть 2: классификация
python main.py --zones        # Часть 3: проверка зон
```

### Запустить с LLM (опционально)

```bash
export GIGACHAT_CREDENTIALS="<ваш-ключ>"   # Linux/macOS
# set GIGACHAT_CREDENTIALS=<ваш-ключ>      # Windows

python main.py --zones --llm
```

Если ключ не задан или GigaChat недоступен - автоматически используется
keyword fallback, и пайплайн отрабатывает корректно.

### Справка по CLI

```bash
python main.py --help
```

## Использование LLM (опционально)

LLM подключается **только** в Части 3 (`check_zone`). Логика:

1. Если `GIGACHAT_CREDENTIALS` задан и библиотека `gigachat` установлена -
   выполняется запрос к GigaChat.
2. При любой ошибке (нет ключа, таймаут, некорректный JSON) -
   автоматический откат на keyword fallback.
3. Части 1 и 2 работают на эвристиках и регулярках всегда.

Это гарантирует, что проверяющий сможет запустить проект локально
без внешних зависимостей.

### Модули

| Модуль | Ответственность |
|---|---|
| `main.py` | CLI, прогон пайплайна, вывод результатов |
| `src/extractor.py` | Часть 1: `extract(text) -> dict` |
| `src/classifier.py` | Часть 2: `classify(text) -> (type, confidence)` |
| `src/zone_checker.py` | Часть 3: `check_zone(note) -> (bool, float, str)` |
| `src/llm_client.py` | Опциональная обёртка GigaChat с graceful degradation |
| `src/patterns.py` | Все регулярки, словари, константы  |
| `src/utils.py` | Нормализация текста, парсинг дат и времени |
| `tests/` | pytest-тесты на все части |

### Ключевые решения

**1. Гибридный подход: эвристики + LLM.**
Базовый пайплайн полностью детерминирован (регулярки, словари, пороги).
LLM подключается опционально и улучшает качество на сложных кейсах.
Если LLM недоступен - работа не прерывается.

**2. Единый источник паттернов - `patterns.py`.**
Все регулярные выражения, словари месяцев и зон, пороги классификации
собраны в одном месте с комментариями.

**3. Явное разграничение Части 1 и Части 3 по зонам.**
В Части 1 зона извлекается **только если явно указана** в тексте.
Семантический анализ зон - задача Части 3.

**4. Порог unknown в классификации.**
`classify` возвращает `unknown`, если топ-1 скор < 0.3 или разрыв
между топ-1 и топ-2 < 0.15. Пороги вынесены в `patterns.py` и
обоснованы в `RESULTS.md`.

**5. Fallback в Части 3.**
`check_zone` сначала пытается использовать LLM, затем - keyword matching.

**6. Парсинг времени сна.**
Поддерживаются 4 формата: `6 ч 30 мин`, `6,5 часов`, `6:30`, `390 минут`.

**7. Парсинг дат.**
Поддерживаются 4 формата: `05.03.2025`, `07.03.25`, `1 марта 2025 г.`,
`03/01/25`. Возвращается ISO-строка.

### Поток данных

```
dataset.json
    │
    ▼
[records] ──► extract() ──► {date, child_id, author, sleep_hours, zone}
    │
    ▼
[records] ──► classify() ──► (type, confidence)
    │
    ▼
[zone_notes] ──► check_zone() ──► (in_zone, confidence, explanation)
                       │
                       └──► LLMClient (опционально) ──► GigaChat
                                                       │
                                                       └─► fallback: keywords
```
